# Vite 빌드 전환 TODO

이 문서는 EDPilot0001의 기존 사이트 생성·배포 흐름을 Vite 기반 산출물로 전환할 때 역할별로 확인할 작업을 정리합니다.

현재 사이트는 Python 도구로 HTML을 생성하고, `tools/package_site.py`가 공개 파일만 `output/site/`에 모은 뒤 GitHub Actions가 이를 GitHub Pages에 배포합니다. Vite 도입은 이 흐름을 바꾸는 선택 사항이며, 브라우저에서 실행되는 파일은 Vite 빌드 뒤에도 공개됩니다. URL이나 클라이언트 코드를 숨기는 수단은 아닙니다.

## 권장 목표 구조

1. Python 콘텐츠·페이지 생성 단계는 유지하고, HTML 생성이 끝난 뒤 Vite가 사이트 자산을 처리하도록 연결합니다.
2. 모든 공개 HTML 페이지를 Vite의 다중 페이지 입력으로 빌드하거나, 현행 페이지 URL을 보존하는 동등한 구성을 선택합니다.
3. 최종 산출물은 `dist/`에 만들고, 검증 통과 후 GitHub Pages에 `dist/`만 게시합니다.
4. 현재 URL, 페이지 간 링크, 다운로드 파일, EduHub 왕복 동작을 유지합니다.
5. API, 사용자 계정, 서버 데이터 저장 요구가 없으면 Backend 서버를 추가하지 않습니다.

- [Backend](backend.md): 정적 사이트 경계 확인, 서버 필요성 판단, 브라우저 저장 데이터
- [QA](qa.md): 기존 사이트와 빌드 결과의 기능·경로 동등성 검증

## 완료 기준

- 정해진 17개 HTML 페이지와 공개 리소스가 빠짐없이 빌드됩니다.
- `/EDPilot0001/` 아래의 기존 페이지 주소와 상대 링크가 동작합니다.
- `dist/`에 공개 대상으로 승인되지 않은 저장소 문서, 테스트, 저작 도구가 들어가지 않습니다.
- 기존 검증 절차와 브라우저 검증이 통과한 산출물만 Pages에 게시됩니다.
- README의 로컬 개발, 빌드, 미리보기 및 배포 설명이 실제 설정과 일치합니다.
